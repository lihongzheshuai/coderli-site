💡 核心算法剖析：为什么“高位逐位贪心”是严格正确的？

按位与（&）的核心特性是：只有两个数在第 $k$ 位同为 1 时，按位与的结果在第 $k$ 位才为 1。

在二进制进制系统中，高位权值具有压倒性优势：
$$2^k > \sum_{j=0}^{k-1} 2^j = 2^k - 1$$ 这意味着：第 $k$ 位为 1，其数值权重严格大于低位所有位全为 1 的总和！

  • 优先保证高位为 1：我们要尽可能让更高位为 1。如果食材集合中存在至少 2 个食材在第 $k$ 位都是 1，那么最终答案的第 $k$ 位一定可以也是必须设为 1！
  • 锁定前缀，继续往下贪心：一旦第 $k$ 位成功置 1，那么后续寻找更低位的 1 时，只能在那些第 $k$ 位（以及之前所有确认保留的高位）都为 1 的食材中继续挑选！因为绝不能为了换取低位的 1 而牺牲已经确立的高位 1。
  • 逐位试探掩码 (Bit Candidate)：从最高位（30 位）循环到第 0 位，每位试探 candidate = ans | (1 << bit)，统计数组中有多少个数满足 (x & candidate) == candidate。若计数 $\ge 2$ 则该位成功保留，否则舍弃。

⚠️ 考场致命陷阱：警惕“从大到小排序取前100”伪解法！

很多初学者在考场上会直觉推测：“最大的按位与肯定产生在最大的那批数里”，于是写出： sort(a, a+n); 仅取最大的 100 个数暴力两两与。

❌ 致命漏洞反例 (点击上方“验真打脸”预设可一键重现)：
假设食材美味度为 [1024, 512, 256, 128, 63, 63]。
排在前面的 4 个大数都是 $2^k$（二进制只有一位 1 且互不重合），它们两两按位与全为 0！
而排在后面的两个较小数 63 (111111₂) 和 63，按位与结果高达 63！
如果只检查前 4 大的数，程序会输出 0，导致严重丢分。

正解的优越性：高位贪心在数学逻辑上无懈可击，时间复杂度仅为 $O(31 \times N)$，在洛谷评测机上 $10^6$ 数据可在 0.05s 左右完美 AC！

💻 满分 AC 代码 (C++ 标准实现) 时间复杂度：O(31 · N) · 空间复杂度：O(N)
#include <iostream> #include <vector> using namespace std; // 针对 N=10^6 的快速输入输出优化 int main() { ios::sync_with_stdio(false); cin.tie(nullptr); int n; if (!(cin >> n)) return 0; vector<int> a(n); for (int i = 0; i < n; ++i) { cin >> a[i]; } int ans = 0; // 累积确认的最高按位与值 // a_i <= 2,147,483,647 = 2^31 - 1，二进制位下标为 30 到 0 for (int bit = 30; bit >= 0; --bit) { int candidate = ans | (1 << bit); // 试探当前位是否可以置 1 int cnt = 0; // 遍历检查有多少个数能包含 candidate 中的所有 1 for (int x : a) { if ((x & candidate) == candidate) { if (++cnt >= 2) break; // 剪枝：只要凑齐 2 个就足够支撑该位 } } // 若至少有 2 个食材支持，则该位确认保留 if (cnt >= 2) { ans = candidate; } } cout << ans << "\n"; return 0; }
